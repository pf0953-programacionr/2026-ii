Introducción

En la lección de introducción a la ciencia de datos se mencionó que el texto de los documentos computacionales se escribe en Markdown. Este capítulo estudia ese lenguaje: qué es, cuáles variantes existen y cuál es su sintaxis. Markdown acompaña todo el trabajo del curso: además del texto de los documentos de Quarto, con él se escriben los archivos README de los repositorios de GitHub y las páginas publicadas con GitHub Pages, que se estudian en la próxima lección, así como la documentación de las tareas y del proyecto final.

Lenguajes de marcado

Un lenguaje de marcado codifica un documento mediante marcas: anotaciones intercaladas en el texto que especifican su estructura (ej. títulos, encabezados), su estilo (ej. negritas, itálicas) o su semántica. El ejemplo más conocido es el Lenguaje de marcado de hipertexto (HTML), con el que se escriben las páginas web.

Markdown es un lenguaje de marcado creado en 2004 por John Gruber, en colaboración con Aaron Swartz, con el objetivo de que un documento fuera fácil de escribir y de leer en su forma original, sin marcas aparatosas, y pudiera convertirse a HTML (Gruber, s. f.). Por esa sencillez se le considera un lenguaje de marcado ligero: sus marcas son signos discretos —numerales, asteriscos, guiones— que no estorban la lectura. Los documentos escritos en Markdown pueden exportarse a una gran variedad de formatos (ej. HTML, DOCX, PDF, LaTeX) para producir páginas web, libros o presentaciones, entre otros.

Variantes de Markdown

La especificación original de Markdown dejó aspectos sin definir, por lo que surgieron variantes (flavors): extensiones o modificaciones que agregan elementos como tablas, notación matemática o código con resaltado de sintaxis. Entre las más relevantes para este curso están:

  • CommonMark: especificación que formaliza y desambigua el Markdown original; sirve de base a muchas otras variantes.
  • GitHub Flavored Markdown (GFM): la variante de GitHub, basada en CommonMark, que agrega tablas y texto tachado, entre otros elementos (GitHub, s. f.). Es la que se usa en los archivos README y otros documentos de los repositorios del curso.
  • Pandoc Markdown: la variante de Pandoc, un conversor entre formatos de documentos, orientada a la escritura técnica y académica. Es la que usa Quarto, el sistema de publicación con el que está construido este sitio web y que se estudiará con detalle más adelante en el curso (Quarto, s. f.).

Puede encontrarse una lista más extensa en Markdown Flavors. Las diferencias entre variantes son menores: la sintaxis básica que estudia este capítulo funciona en todas las herramientas del curso (RStudio, GitHub y Quarto).

Ejemplo de documento

El siguiente es un ejemplo de documento en Markdown, con marcas para un encabezado, negritas, itálicas, un hipervínculo y una imagen.

# Los satélites galileanos

Se llaman **satélites galileanos** los cuatro satélites
de Júpiter descubiertos en 1610 por
[Galileo Galilei](https://es.wikipedia.org/wiki/Galileo_Galilei):
*Ío*, *Europa*, *Ganimedes* y *Calisto*.
Son los más grandes de los satélites de Júpiter,
siendo visibles incluso con telescopios de baja potencia.

![Júpiter y los satélites galileanos](https://upload.wikimedia.org/wikipedia/commons/f/fe/Jupiter_and_the_Galilean_Satellites.jpg)

El documento se visualiza de la siguiente manera:

Los satélites galileanos

Se llaman satélites galileanos los cuatro satélites de Júpiter descubiertos en 1610 por Galileo Galilei: Ío, Europa, Ganimedes y Calisto. Son los más grandes de los satélites de Júpiter, siendo visibles incluso con telescopios de baja potencia.

El contenido de este ejemplo está basado en el artículo Satélite galileano de Wikipedia; la imagen, referenciada directamente desde Wikimedia Commons, es un montaje de la misión Galileo (NASA/JPL/DLR, dominio público).

Sintaxis

En esta sección se explican los principales elementos de la sintaxis de Markdown y se muestran sus salidas. Una referencia completa puede consultarse en Markdown Guide (s. f.).

Encabezados

Hay seis niveles de encabezados, del 1 (letras más grandes) al 6 (letras más pequeñas). Se especifican con símbolos de numeral (#) antes del texto (note el espacio entre el último numeral y el inicio del texto). La tabla 1 muestra los seis niveles.

Para los niveles 1 y 2 existe una sintaxis alterna: una línea de símbolos de igual (===) o de guiones (---) bajo el texto del encabezado.

Párrafos y cambios de línea

Los párrafos se separan con al menos una línea en blanco; un simple cambio de línea no genera un párrafo nuevo. Si se requiere un cambio de línea sin separar párrafos, se agregan dos espacios al final de la línea o una barra invertida (\).

Este es el primer párrafo de un documento.

Este es el segundo párrafo,
escrito en dos líneas que forman un solo párrafo.

Negrita, itálica y tachado

La negrita se marca con dos asteriscos (**) o dos guiones bajos (__) antes y después del texto; la itálica, con un asterisco (*) o un guion bajo (_); y el tachado —una extensión de GFM— con dos virgulillas (~~). La tabla 2 resume estas marcas.

Listas

Las listas numeradas se definen con números seguidos de punto (1., 2., 3., …) antes de cada elemento; las no numeradas, con guiones (-) o asteriscos (*). Un elemento se anida dentro de otro sangrándolo con espacios. Las listas deben separarse del párrafo anterior con una línea en blanco; de lo contrario, algunos renderizadores —como el de GitHub— las muestran como texto corrido, uno de los errores más frecuentes al empezar a usar Markdown. La tabla 3 muestra ambos tipos de lista.

En GFM, una lista no numerada se convierte en lista de tareas agregando corchetes después del guion: - [ ] marca una tarea pendiente y - [x] una completada. GitHub las muestra como casillas de verificación; son comunes en los archivos README y en el seguimiento de trabajo pendiente.

Enlaces e imágenes

Un enlace (hipervínculo) se define con paréntesis cuadrados ([]), que contienen el texto del enlace, seguidos de paréntesis redondos (()), que contienen la dirección del documento al que conduce. Una imagen usa la misma sintaxis precedida por un signo de admiración de cierre (!); los paréntesis cuadrados contienen entonces un texto alternativo, que se muestra cuando la imagen no puede desplegarse y que utilizan los lectores de pantalla para describirla, por lo que conviene redactarlo siempre. La tabla 4 muestra ambos elementos.

La dirección de una imagen puede ser local —un archivo en la misma computadora que el documento, como img/mapa.png— o remota —un archivo en otra computadora, al que se accede mediante una URL, como la imagen de Júpiter de los ejemplos, que se carga directamente desde Wikimedia Commons—. Una imagen local requiere que el archivo acompañe siempre al documento; una remota depende de que el sitio que la aloja se mantenga disponible.

Citas textuales

Se especifican con un símbolo de «mayor que» (>) antes de cada línea.

> Caminante, no hay camino,
> se hace camino al andar.

El texto anterior se visualiza así:

Caminante, no hay camino, se hace camino al andar.

Código

El código se distingue del resto del texto con acentos graves (backticks, `). Un fragmento dentro de un renglón se delimita con un acento grave a cada lado; por ejemplo, `print()` se visualiza como print(). Un bloque de código se delimita con líneas de tres acentos graves; en la primera puede indicarse el lenguaje, para que el código se muestre con resaltado de sintaxis:

```r
dias <- 7
horas <- dias * 24
print(horas)
```

El bloque anterior se visualiza así:

dias <- 7
horas <- dias * 24
print(horas)

El texto dentro de las marcas de código se muestra tal cual, sin interpretar otras marcas de Markdown: por eso este capítulo las usa para mostrar la sintaxis sin que se convierta en salida.

Tablas

Las tablas —una extensión de GFM— se construyen con barras verticales (|) que separan las columnas y una línea de guiones que separa el encabezado del resto de las filas (GitHub, s. f.):

| Provincia | Capital  |
|-----------|----------|
| San José  | San José |
| Alajuela  | Alajuela |
| Cartago   | Cartago  |

La tabla se visualiza de la siguiente manera:

Provincia Capital
San José San José
Alajuela Alajuela
Cartago Cartago

Con dos puntos en la línea de guiones se controla la alineación de cada columna: :--- a la izquierda, :---: al centro y ---: a la derecha.

Notación matemática

Muchas variantes de Markdown —entre ellas las de GitHub y de Quarto (este sitio)— permiten escribir expresiones matemáticas con la sintaxis de LaTeX, delimitadas con un símbolo de dólar ($) si van dentro de un renglón o con dos ($$) si van en su propio bloque. Por ejemplo, la sintaxis:

La densidad de población se calcula como:

$$d = \frac{P}{A}$$

donde $P$ es la población y $A$ el área.

se visualiza así:

La densidad de población se calcula como:

\[d = \frac{P}{A}\]

donde \(P\) es la población y \(A\) el área.

Los detalles de la sintaxis de las expresiones pueden consultarse en el wikilibro LaTeX/Mathematics (s. f.).

HTML dentro de Markdown

Markdown acepta HTML intercalado en el documento, lo que permite lograr efectos para los que no tiene marcas propias. Tres usos frecuentes en este curso:

  • Superíndices y subíndices, con los elementos <sup> y <sub>: km<sup>2</sup> se visualiza como km2, y CO<sub>2</sub> como CO2.
  • Comentarios, con la marca <!-- ... -->: el texto que contiene no aparece en la salida, lo que permite dejar notas o recordatorios en la fuente del documento. Por ejemplo: <!-- Pendiente: actualizar la tabla -->.
  • Tamaño de las imágenes, con los atributos height y width del elemento img, que especifican la altura y el ancho en pixeles; si se usa solo uno, el otro se ajusta automáticamente para conservar las proporciones. Por ejemplo: <img src="jupiter.jpg" height="50" alt="Júpiter y sus satélites">.

Otros elementos

  • Una línea horizontal se genera con una línea de tres o más guiones (---) o asteriscos (***), separada del texto por líneas en blanco.
  • Para mostrar literalmente un carácter que Markdown interpretaría como marca, se antepone una barra invertida: \*asteriscos visibles\* se visualiza como *asteriscos visibles*.
  • Los diagramas de este sitio web —como los de las lecciones de introducción a la ciencia de datos y de Git, GitHub y GitHub Pages— se escriben dentro del propio Markdown, como bloques de código en el lenguaje de Mermaid, una extensión que GitHub y Quarto convierten en diagramas.

Resumen

  • Un lenguaje de marcado codifica la estructura, el estilo y la semántica de un documento mediante marcas intercaladas en el texto; Markdown es un lenguaje de marcado ligero, diseñado para que el documento sea legible aun en su forma original.
  • Sus variantes extienden la especificación original; la sintaxis básica es común a las herramientas del curso: los documentos de GitHub (GFM) y los documentos de Quarto (Pandoc Markdown), como los de este sitio web.
  • Las marcas principales cubren encabezados (#), negrita (**), itálica (*), listas (1., -), enlaces ([]()), imágenes (![]()), citas (>), código (`), tablas (|) y notación matemática ($).
  • El HTML intercalado complementa a Markdown en lo que este no cubre, como superíndices y subíndices o el tamaño de las imágenes.
