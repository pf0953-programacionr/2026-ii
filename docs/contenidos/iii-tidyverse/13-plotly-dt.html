Introducción

Los gráficos del capítulo anterior son estáticos: imágenes que muestran lo que su autor decidió mostrar. En una página web, un gráfico puede además ser interactivo: quien lo lee pasa el cursor sobre un punto y ve a qué observación corresponde, acerca una región amontonada, oculta una categoría con un clic en la leyenda o descarga el gráfico como imagen. Lo mismo ocurre con las tablas: una tabla interactiva se ordena por cualquier columna, se pagina y se filtra con un cuadro de búsqueda, de modo que una tabla de 84 cantones —o de 8 400 registros— cabe en un documento sin abrumarlo.

Esa interactividad la aporta JavaScript, el lenguaje de programación de los navegadores web. No hace falta aprenderlo: una familia de paquetes de R, construidos sobre htmlwidgets, «envuelve» bibliotecas de JavaScript y las pone a disposición desde R. En este curso se usan tres: plotly para gráficos, DT para tablas y, en la sección IV, leaflet para mapas. En el ejemplo de la semana 1 ya aparecieron plotly y leaflet; ahora se ve cómo se construyen.

Este capítulo presenta plotly a partir de lo que ya se sabe de ggplot2 —la función ggplotly() convierte un gráfico de ggplot2 en uno interactivo— y DT para las tablas, y termina con lo que hay que saber para incluirlos en un documento Quarto. Los gráficos y tablas interactivos solo funcionan en salidas HTML: en el sitio de cada estudiante en GitHub Pages, en los tableros de control y en las aplicaciones shiny de las secciones siguientes. Se continúa con el hilo conductor del curso: la población y la extensión de los 84 cantones de Costa Rica (INEC, 2023).

library(tidyverse)
library(plotly)
library(DT)

cantones <- read_csv("https://raw.githubusercontent.com/pf0953-programacionr/2026-ii/main/datos/cantones.csv") |>
  mutate(
    densidad = poblacion / area_km2,
    tipo = if_else(densidad > 100, "urbano", "rural")
  )

Al cargar plotly después del tidyverse aparece un mensaje que dice que algunos objetos quedan «enmascarados» (masked): last_plot de ggplot2, filter de stats y layout de graphics. No es un error: plotly define funciones con esos nombres, y la que importa, filter(), sigue siendo la de dplyr. Como en los capítulos anteriores, el bloque lleva message: false para que el mensaje no aparezca en el documento.

Gráficos interactivos con plotly

plotly es el paquete de R de la biblioteca de JavaScript plotly.js, que también tiene versiones para Python, Julia y otros lenguajes. Puede usarse de dos maneras: convirtiendo un gráfico de ggplot2 con ggplotly(), o construyendo el gráfico desde cero con plot_ly(), su propia gramática. En este curso se usa la primera, porque aprovecha todo lo aprendido en el capítulo anterior; la segunda se presenta brevemente al final de la sección.

De ggplot2 a plotly

El punto de partida es el gráfico que se dejó listo para presentar en el capítulo anterior:

grafico <- ggplot(cantones, aes(x = area_km2, y = poblacion, color = tipo)) +
  geom_point(size = 2, alpha = 0.8) +
  scale_x_log10(labels = scales::label_number(big.mark = " ")) +
  scale_y_log10(labels = scales::label_number(big.mark = " ")) +
  scale_color_manual(values = c(rural = "#4f7d3a", urbano = "#005da4")) +
  labs(
    title = "Área y población de los cantones de Costa Rica",
    subtitle = "Estimación de población de 2022; ejes en escala logarítmica",
    x = "Área (km²)",
    y = "Población (habitantes)",
    color = "Tipo de cantón",
    caption = "Fuente: INEC (2023)"
  ) +
  theme_minimal() +
  theme(legend.position = "bottom")

La función ggplotly() recibe el objeto de ggplot2 y devuelve un gráfico interactivo:

ggplotly(grafico)

Pruebe el gráfico: pase el cursor sobre un punto para ver sus valores en la etiqueta emergente (tooltip); arrastre un rectángulo sobre la esquina superior izquierda, donde se amontonan los cantones urbanos, para acercarla, y haga doble clic para volver; haga clic en «rural» en la leyenda para ocultar esos cantones y otro clic para mostrarlos de nuevo; y use la barra de herramientas que aparece arriba a la derecha, con el botón de la cámara que descarga el gráfico como imagen PNG.

ggplotly() traduce casi todo el gráfico, pero no todo. La tabla 1 resume qué se conserva y qué se pierde; lo más visible es que el subtítulo y la nota al pie (caption) desaparecen, porque plotly no tiene equivalentes directos. Si la fuente de los datos debe quedar en el gráfico interactivo, se escribe en el título o en el texto del documento.

La etiqueta emergente

Por defecto, la etiqueta emergente muestra las variables mapeadas a las estéticas —area_km2, poblacion, tipo—, con el nombre de la columna y el valor sin formato. Para explorar los datos eso no basta: lo que se quiere saber al pasar el cursor por un punto es cuál cantón es. La solución es mapear una estética adicional, text, con el contenido de la etiqueta, y pedirle a ggplotly() que muestre solo esa estética con el argumento tooltip. ggplot2 no conoce la estética text y la ignora al dibujar, pero plotly sí la usa.

El contenido se construye con paste0(), que une textos y valores; "\n" es un salto de línea, y las funciones del paquete scales (number()) dan formato a los números, como se hizo con los ejes en el capítulo anterior:

grafico_interactivo <- ggplot(
  cantones,
  aes(
    x = area_km2,
    y = poblacion,
    color = tipo,
    text = paste0(
      canton, " (", provincia, ")",
      "\nPoblación: ", scales::number(poblacion, big.mark = " "),
      "\nÁrea: ", scales::number(area_km2, accuracy = 0.1, big.mark = " "), " km²",
      "\nDensidad: ", scales::number(densidad, accuracy = 1, big.mark = " "), " hab./km²"
    )
  )
) +
  geom_point(size = 2, alpha = 0.8) +
  scale_x_log10(labels = scales::label_number(big.mark = " ")) +
  scale_y_log10(labels = scales::label_number(big.mark = " ")) +
  scale_color_manual(values = c(rural = "#4f7d3a", urbano = "#005da4")) +
  labs(
    title = "Área y población de los cantones de Costa Rica (INEC, 2023)",
    x = "Área (km²)",
    y = "Población (habitantes)",
    color = "Tipo de cantón"
  ) +
  theme_minimal()

ggplotly(grafico_interactivo, tooltip = "text")

Ahora el gráfico responde la pregunta que quedó abierta en el capítulo anterior sin necesidad de rotular los puntos: el cantón más poblado es San José, el más extenso es San Carlos, y los cantones urbanos pequeños de la esquina superior izquierda se identifican uno por uno.

La estética text se escribe en el aes() de ggplot(), no en el de la geometría: si se pone en geom_point(aes(text = …)), ggplot2 emite la advertencia Ignoring unknown aesthetics: text, que no impide que funcione pero ensucia el documento. Y, como la estética no existe para ggplot2, el objeto grafico_interactivo también se puede mostrar como gráfico estático: la etiqueta simplemente no se dibuja.

Configuración

El objeto que devuelve ggplotly() se puede seguir modificando con el pipe y dos funciones de plotly: config(), para la barra de herramientas y el comportamiento general, y layout(), para la apariencia (títulos, ejes, leyenda, márgenes). Dos opciones de config() conviene usarlas siempre en documentos en español: locale = "es" traduce los textos de la barra de herramientas y los formatos de fecha, y displaylogo = FALSE quita el logotipo de Plotly.

ggplotly(grafico_interactivo, tooltip = "text") |>
  config(locale = "es", displaylogo = FALSE)

El mismo procedimiento sirve para cualquier gráfico del capítulo anterior. Por ejemplo, el gráfico de barras de la población por provincia, con la población formateada en la etiqueta emergente:

grafico_barras <- cantones |>
  group_by(provincia) |>
  summarize(poblacion = sum(poblacion)) |>
  ggplot(aes(
    x = poblacion,
    y = fct_reorder(provincia, poblacion),
    text = paste0(provincia, ": ", scales::number(poblacion, big.mark = " "), " habitantes")
  )) +
  geom_col(fill = "#005da4") +
  scale_x_continuous(labels = scales::label_number(big.mark = " ")) +
  labs(
    title = "Población de las provincias de Costa Rica (INEC, 2023)",
    x = "Población (habitantes)",
    y = NULL
  ) +
  theme_minimal()

ggplotly(grafico_barras, tooltip = "text") |>
  config(locale = "es", displaylogo = FALSE)

La gramática propia de plotly

plotly tiene además su propia gramática, con la función plot_ly(): recibe el data frame, las columnas de cada eje precedidas por una virgulilla (~, como en facet_wrap()) y el tipo de gráfico (type); layout() agrega los títulos. Es la que se usó en el ejemplo de la semana 1, y la que hace falta para los tipos de gráficos que ggplotly() no traduce, como los de pastel o los tridimensionales. El gráfico de barras anterior, con plot_ly():

cantones |>
  group_by(provincia) |>
  summarize(poblacion = sum(poblacion)) |>
  plot_ly(
    x = ~poblacion,
    y = ~provincia,
    type = "bar",
    orientation = "h",
    marker = list(color = "#005da4")
  ) |>
  layout(
    title = "Población de las provincias de Costa Rica (INEC, 2023)",
    xaxis = list(title = "Población (habitantes)"),
    yaxis = list(title = "", categoryorder = "total ascending")
  ) |>
  config(locale = "es", displaylogo = FALSE)

Las dos gramáticas producen el mismo resultado. En este curso se prefiere ggplotly(): un solo código sirve para el gráfico estático de un documento impreso y para el interactivo de una página web, y lo aprendido sobre la gramática de gráficos no se desperdicia. La documentación de plotly (Plotly, s. f.) describe plot_ly() con detalle para quien la necesite.

Tablas interactivas con DT

Hasta ahora las tablas se han mostrado imprimiendo el data frame, lo que en un documento Quarto produce un listado de texto, útil para una decena de filas y poco más. DT es el paquete de R de la biblioteca de JavaScript DataTables: su función datatable() convierte cualquier data frame en una tabla interactiva, paginada, que se ordena con un clic en el encabezado de una columna y se filtra con el cuadro de búsqueda.

datatable(cantones)

Pruebe la tabla: ordene por densidad con dos clics en su encabezado (el primero ordena de menor a mayor; el segundo, de mayor a menor), escriba «Heredia» en el cuadro de búsqueda y cambie la cantidad de filas por página.

Opciones

La tabla anterior muestra los datos tal cual: nombres de columnas en el formato del código, números sin formato, un número de fila que no aporta nada y los controles en inglés. datatable() y las funciones format*() de DT permiten dejarla lista para presentar. La tabla 2 recoge los argumentos más usados.

Como con ggplot2, dplyr prepara los datos —aquí, selecciona y ordena las columnas— y los pasa a datatable(), que recibe el data frame por el pipe; las funciones format*() se encadenan después, también con el pipe:

cantones |>
  select(provincia, canton, poblacion, area_km2, densidad, tipo) |>
  arrange(desc(densidad)) |>
  datatable(
    rownames = FALSE,
    colnames = c("Provincia", "Cantón", "Población", "Área (km²)", "Densidad (hab./km²)", "Tipo"),
    filter = "top",
    options = list(
      pageLength = 10,
      language = list(url = "//cdn.datatables.net/plug-ins/2.3.2/i18n/es-ES.json")
    )
  ) |>
  formatRound(columns = "poblacion", digits = 0, mark = " ") |>
  formatRound(columns = c("area_km2", "densidad"), digits = 1, mark = " ")

Con el filtro de la columna «Densidad», arrastre el control deslizante para quedarse con los cantones de más de 1 000 habitantes por kilómetro cuadrado: son 16, nueve de ellos en San José y cinco en Heredia. Observe que formatRound() recibe los nombres originales de las columnas (poblacion, no «Población»), porque colnames solo cambia lo que se muestra.

La traducción se carga desde Internet cada vez que se abre el documento; si la tabla debe funcionar sin conexión, language admite en su lugar una lista con los textos (list(search = "Buscar:", …)), como se describe en la documentación de DT.

Cuándo no usar una tabla interactiva

Una tabla interactiva es la herramienta para que quien lee explore muchas filas. No lo es para una tabla pequeña de resultados —las siete provincias de resumen_provincias—, que se lee mejor completa y quieta: para eso está knitr::kable(), que produce una tabla estática y funciona también en PDF y Word. Tampoco lo es para un data frame enorme: datatable() copia todas las filas al documento HTML, de modo que una tabla de cien mil filas lo vuelve lento o inservible; antes hay que filtrar o resumir con dplyr.

cantones |>
  group_by(provincia) |>
  summarize(cantones = n(), poblacion = sum(poblacion), area_km2 = sum(area_km2)) |>
  mutate(densidad = poblacion / area_km2) |>
  arrange(desc(densidad)) |>
  knitr::kable(
    digits = 1,
    format.args = list(big.mark = " "),
    col.names = c("Provincia", "Cantones", "Población", "Área (km²)", "Densidad (hab./km²)")
  )

Gráficos y tablas interactivos en documentos Quarto

Los gráficos de plotly y las tablas de DT son htmlwidgets: fragmentos de HTML y JavaScript que Quarto inserta en el documento tal como inserta una imagen. Tres consecuencias prácticas:

  • Solo funcionan en formatos HTML. Si el mismo documento se procesa a PDF o a Word, Quarto intenta sustituirlos por una captura de pantalla estática (lo que requiere paquetes adicionales) o los omite. Para un documento que deba salir en ambos formatos, los gráficos se construyen con ggplot2 y se muestran con ggplotly() solo en la versión HTML, o se dejan estáticos.
  • Las opciones de figura del capítulo anterior funcionan: un bloque con una etiqueta fig-… y fig-cap numera el gráfico interactivo como una figura más y permite citarlo con @fig-…, y fig-height fija su alto (en pulgadas, como en las figuras estáticas). El ancho de un htmlwidget es siempre el disponible en la página, de modo que fig-width no tiene efecto visible.
  • Con embed-resources: true, las bibliotecas de JavaScript de plotly y de DT se incrustan en el archivo HTML, que crece unos 4 MB con el primer gráfico interactivo y la primera tabla; los siguientes agregan poco. Sigue siendo un solo archivo que se sube a GitHub Pages como hasta ahora, pero conviene saberlo si el documento debe enviarse por correo.

Clínica de errores

La tabla 3 recoge los problemas más frecuentes al empezar con plotly y DT.

Resumen

  • Los htmlwidgets son paquetes de R que envuelven bibliotecas de JavaScript para producir gráficos, tablas y mapas interactivos, que funcionan únicamente en salidas HTML.
  • ggplotly() convierte un gráfico de ggplot2 en un gráfico interactivo de plotly, con etiquetas emergentes, acercamiento, leyenda activa y descarga como imagen; se pierden el subtítulo y la nota al pie.
  • La etiqueta emergente se controla con la estética text (en el aes() de ggplot(), construida con paste0() y formateada con scales) y el argumento tooltip = "text"; config(locale = "es", displaylogo = FALSE) traduce los controles y quita el logotipo.
  • plot_ly() es la gramática propia de plotly, necesaria para los gráficos que ggplotly() no traduce.
  • datatable(), de DT, convierte un data frame en una tabla interactiva paginada, ordenable y filtrable; rownames, colnames, filter, options y las funciones format*() la dejan lista para presentar. Para tablas pequeñas, knitr::kable() produce una tabla estática.
  • En Quarto, los htmlwidgets se insertan como las figuras, aceptan fig-cap y aumentan el tamaño del archivo HTML con embed-resources: true.
